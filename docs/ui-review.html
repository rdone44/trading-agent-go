交易工作台 UI 评审与优化方案

评审对象：internal/webui/static/ 单页交易终端（index.html 411 行 / app.css 325 行 / app.js 1684 行）

评审人UiDesigner
日期2026-10-09
界面规模3 路由 · 9 面板 · 1 抽屉
技术栈原生 HTML/CSS/JS · 零依赖

结论先行：这套 UI 的架构判断力高于其视觉完成度。信息分区、路由设计、安全语义（纸面/实盘分级、危险操作二次确认、fail-open 说明）都达到了成熟交易终端的水平，代码组织也干净。但它在三个地方系统性失分：① 颜色语义与中文金融惯例相反；② 小屏与 1000–1150px 区间存在真实布局故障；③ 信息密度与层级结构不匹配——最重要的账户与持仓，被塞进了最不显眼的角落。下面逐项给出证据与可直接落地的修复。

■ 做对了的（应保留）
  • 路由与草稿保留：hash 路由切页不销毁表单实例，草稿不丢，是有经验的产品判断。
  • 图表不引依赖：K 线与权益曲线用内联 SVG 手写，零运行时依赖，preserveAspectRatio="none" 自适应。
  • 安全语义成体系：纸面/实盘在顶栏、安全条、风控卡、开关四处一致出现；实盘需输入「确认实盘」；停止不平仓有专属对话框。
  • 状态即文案：空状态、错误态、降级态都有明确中文说明（fail-open 会讲清楚「照常放行」）。
  • 输入容错：invalid 事件会自动跳到出错字段所在页并展开 details，细节到位。
■ 必须改的（本次重点）
  • 涨跌色反了：代码里涨=绿、跌=红，与 A 股/国内用户直觉相反（P0）。
  • 中屏布局故障：.rail 在 <1150px 变成覆盖抽屉，但「设置」按钮 #rail-toggle 的 JS 逻辑与栅格断点不一致（P0）。
  • 层级倒置：权益数字 27px 却排在行情图之下，持仓与风控挤在同宽两列（P1）。
  • 可用性硬伤：顶栏行情不自增、表格无排序、日志无法暂停滚动、缺少连接状态骨架（P1）。
  • 设计令牌分裂：报告页 report.html 是浅色米黄主题，与工作台深色主题完全无关（P2）。

03P0 · 必须立即修复

F-01

涨跌配色与中文金融惯例相反

颜色语义错误 · 影响所有行情、持仓与成交展示

严重

当前主题把「涨」定义为青绿色 --up: #55c6a2，把「跌」定义为粉红色 --down: #f18087——这是欧美惯例。而中国用户在 A 股、港股、国内行情软件中形成的肌肉记忆是红涨绿跌。结果是：一笔 +18% 的浮盈显示为绿色、止损告警显示为红色，方向感是反的。

代码证据 app.css:6 → --up: #55c6a2; --up-dim: #19352f; --down: #f18087; --down-dim: #39252c;
app.js:52 → const signClass = (v) => (ok(v) ? (v >= 0 ? "pos" : "neg") : "");
app.css:151-152 → .pos { color: var(--up); } .neg { color: var(--down); }

注意这不是简单的「两个变量对调」：--down 同时被用作危险/错误/止损语义（.btn.danger、.alert、.safety-strip.warn、.gauge-fill.hot、熔断提示）。如果直接把 --down 改成绿色，整个风控体系会变成「绿色告警」。

当前（欧美惯例） 盈利 +18.00% · 亏损 −6.20%
止损离场标签为红色，与「亏损红」混为一谈。
目标（中文惯例） 盈利 +18.00% · 亏损 −6.20%
危险语义拆成独立变量 --danger，恒为红色。
建议实现：语义拆分，而非变量对调 新增一组与涨跌解耦的语义色，让「方向」和「风险」各管各的： 
/* 方向色：遵循中文金融惯例，红涨绿跌 */
--up: #55c6a2;   --up-dim: #19352f;
--down: #f18087; --down-dim: #39252c;
--rise: #e05a4f;  --rise-dim: #3b2320;   /* 上涨 / 盈利 → 红 */
--fall: #37b98a;  --fall-dim: #16352b;   /* 下跌 / 亏损 → 绿 */

/* 风险色：与方向无关，恒为红 */
--danger: #f18087; --danger-dim: #39252c;
--warn:   #dfbc75; --warn-dim:   #352d21;

/* 兼容别名：现有 .pos/.neg 自动跟随新语义 */
.pos { color: var(--rise); }
.neg { color: var(--fall); }
然后把风控相关的 var(--down) 全部改为 var(--danger)，仅保留 .neg、K 线阴线、盈亏数字使用 --fall。建议新增一个 .dir-rise / .dir-fall 类名，避免后人再把两个语义混用。
F-02

侧边抽屉开关逻辑与栅格断点不一致

响应式故障 · 1000–1150px 区间设置抽屉不可达

严重

侧边栏 .rail 是 position: fixed 且默认 transform: translateX(100%); visibility: hidden——也就是说它永远是一个覆盖式抽屉，永远不会进入栅格。但代码注释与 .board 的网格定义（grid-template-areas 中并没有 rail）暗示它曾有「宽屏入栅格」的设计意图。

矛盾点在于：.board 在 1150px 才收窄，而 setRail() 的注释写的是「below 1000px it becomes an overlay」。实际效果是任何宽度下设置都只能通过抽屉打开，而 <560px 时 #setup-shortcut 又被 display:none 隐藏，窄屏用户只能靠顶栏的「设置」按钮，而该按钮在窄屏下与「开始交易 / 立即执行 / 停止策略」挤在同一行 .strip-actions 中，容易换行错位。

代码证据 app.css:189 → .rail { position: fixed; ... transform: translateX(100%); visibility: hidden; }
app.css:74-78 → .board 的 grid-template-areas 只有 market/account/position/log/risk，没有 rail
app.css:274 → @media (max-width:560px){ #setup-shortcut { display: none; } }
app.js:190-191 → 注释声称 1000px 以下才需要显式开合，与 CSS 实际不符
建议实现 方案 A（推荐，改动最小）：承认抽屉是唯一形态，删掉误导性注释，并把断点统一到 1150px；同时在 <560px 保留 #setup-shortcut 但改为图标按钮，避免与安全条争抢。

方案 B（体验更好）：≥1500px 时让 rail 真正入栅格成为第三列（grid-template-columns: 240px minmax(0,1fr) 380px），交易终端的大屏用户可同时看到设置与行情，减少一次开合操作。
F-03

行情时间戳不自增，过期数据无告警

信任问题 · 用户无法判断看到的是否是「此刻」

严重

顶栏的 #ticker-time 只在 renderMarket() 被调用时写入一次。refreshMarket() 的轮询是 15 秒，失败时退避到 30 秒——也就是说刷新间隔内时间文案是冻结的。行情更新失败时虽然会把 #market-state 改成「行情过期 · 重连中」，但顶栏大号价格数字仍然保持原样且颜色不变。

代码证据 app.js:264 → marketTimer = setTimeout(refreshMarket, 15000);（成功）
app.js:271 → marketTimer = setTimeout(refreshMarket, 30000);（失败退避）
app.js:281 → $("#ticker-time").textContent = fmt.clock(market.updated_at); ← 仅在渲染时写一次
app.js:266-267 → 失败时只改 #market-state 与图表，顶栏价格无任何过期标记
建议实现 三件事一起做：① 用 1 秒 setInterval 单独驱动一个「数据新鲜度」指示器，显示 3s 前 而非绝对时间，超阈值变色；② 行情过期时给顶栏价格加 .stale 类（降透明度 + 右上角琥珀色警示点）；③ 在 .market-state 旁加一个 aria-live="polite" 的隐藏告警，读屏用户也能获知。 
// 新增：独立的新鲜度心跳，与行情请求解耦
let marketTickTimer = null;
function startFreshnessTick() {
  clearInterval(marketTickTimer);
  marketTickTimer = setInterval(() => {
    if (!market?.updated_at) return;
    const age = (Date.now() - new Date(market.updated_at)) / 1000;
    $("#ticker-time").textContent = age < 5 ? "刚刚" : `${Math.round(age)}s 前`;
    $("#ticker-price").classList.toggle("stale", age > 45);
  }, 1000);
}
配套 CSS：.quote-price.stale { opacity:.55 }，并在其后用 ::after 加一个小圆点。

04P1 · 建议本轮迭代完成

F-04

登录卡横跨整行，未登录时把行情图挤到第二屏

信息层级 · 首次访问体验

中等

.board 的第一行网格区域被 auth auth 独占。当 authEnabled 为真且未登录时，一整张登录卡占据首屏，把产品最有价值的实时 K 线推到折叠线以下。

代码证据 app.css:74-78 → grid-template-areas: "auth auth" "market market" ...
app.js:866 → card.hidden = !authEnabled || signedIn;
建议实现 未登录时把登录卡收成 顶栏右侧的一个紧凑入口（「登录以启用交易 →」）；点击后以模态或右抽屉形式展开登录表单。行情图从此恒定位于首屏。若必须保留卡内嵌形式，则把 auth 与 market 合并到同一行（grid-template-columns: 340px minmax(0,1fr)），让登录卡成为左侧窄列。
F-05

核心数字的视觉权重与位置不匹配

信息层级 · 交易终端的第一性问题

中等

终端用户最先想知道的是「我现在赚了多少、还有多少风险敞口」。但当前网格顺序把 market（K 线）放在整行主位，account 与 position 被压到第二行等宽两列，equity-value 尽管是全页最大的字（27px），却出现在首屏之外。

当前布局 第一行：登录卡（整行）
第二行：K 线图（整行，248px 高）
第三行：资金与收益 ｜ 持仓
第四行：运行日志 ｜ 风控与策略
建议布局（≥1150px） 第一行：资金与收益 ｜ 持仓（含止损位置条）
第二行：K 线图（整行，≥320px）
第三行：风控与策略 ｜ 运行日志
登录入口移至顶栏，不再占行
建议实现 重排 grid-template-areas，只在 <850px 时把行情提到最前（移动端确实先看价格）： 
.board {
  grid-template-areas:
    "account position"
    "market  market"
    "risk    log";
}
/* 移动端反过来：先价格，再资金 */
@media (max-width:850px){
  .board { grid-template-areas: "market" "account" "position" "risk" "log"; }
}
另建议把 .big 从 27px 提到 30–32px，并给 .account-body 加一条同涨跌色的左侧 3px 竖条，让「账户状态」在余光中即可辨识。
F-06

数据表不可排序、不可筛选、无列固定

可用性 · 订单/成交/日志三大表的通用短板

中等

三个表格都由同一个 table(headers, rows, emptyMessage) 生成，只做 reverse() 后正序渲染，没有任何排序入口。当成交记录或运行日志累积到几十上百行后，用户无法按盈亏、按方向、按离场原因快速定位。同时 td.note 被限制在 220–460px，其余列 white-space: nowrap，窄屏必然横向滚动。

代码证据 app.js:336-341 → function table(headers, rows, emptyMessage) 无交互参数
app.js:676 → [...log].reverse()（固定倒序）
app.css:167 → th, td { white-space: nowrap; }
app.css:173 → td.note { min-width:220px; max-width:460px; }
建议实现 ① 给 table() 增加第三个可选参数 options.sortable，表头点击切换排序（数值列按数字、时间列按时间），并在 th 上用 aria-sort 暴露状态；② 数值列统一加 font-variant-numeric: tabular-nums，避免数字宽度跳动；③ 时间列改为相对时间（12:04:31 → 3 分钟前，hover 显示完整时间戳），可显著压缩列宽；④ 给 .panel-scroll 加 overscroll-behavior: contain，防止横向滚动带动整页。
F-07

日志区缺少「跟随最新」与暂停滚动

可用性 · 运行中追日志的核心操作

中等

策略运行时每 3 秒轮询一次并整体重绘表格（renderTab() → innerHTML 全量替换）。这带来两个问题：① 表格每次重建，用户滚动位置与文本选择会丢失；② 新行出现在顶部（reverse()），用户正在读的行会不断被向下推。

建议实现 在 .log 面板头部右侧加一个「跟随最新」开关（默认开）。开启时保持当前倒序置顶行为；用户手动向上滚动即自动解除跟随，并在右下角浮出「↓ 有 N 条新记录」按钮，点击后回到顶部并恢复跟随。实现上建议改为增量渲染（只 append 新行 + aria-live="polite"），避免全量 innerHTML 重建导致的选择丢失。
F-08

全局提示条无超时、无关闭、无队列

可用性 · 错误提示可能永久遮挡界面

中等

setStatus() 只有一个固定定位的 #status 元素，position: fixed; bottom: 18px; left: 50%，位于底部中央——恰好覆盖日志表格的最后一两行。错误状态下不会自动消失，也没有关闭按钮；下一条提示直接覆写上一条，历史信息全部丢失。

代码证据 app.js:180-186 → function setStatus(message, kind)，无 timer、无 dismiss
app.css:236 → .status { position: fixed; bottom: 18px; left: 50%; z-index: 95; }
建议实现 改造成 toast 栈：① 成功/信息类 4 秒后自动淡出，错误类需手动关闭或停留 12 秒；② 支持多条纵向堆叠（最多 3 条，超出折叠为「+2 条」）；③ 加 role="status" / 错误用 role="alert"，并避免遮住 .panel-scroll——建议移到右上角，与内容区互不干扰。
F-09

缺少骨架屏，加载过程只有一行小字

感知性能 · 首屏与切页

中等

K 线加载态是 <div class="market-empty">正在加载 Binance 行情…</div>，资金与持仓在会话未启动时显示一串 —。整个首屏在数据到达前是「空的且有跳变」：数字从 — 突然变成 27px 大数，卡片高度会抖动（CLS）。

建议实现 ① 为 K 线区、权益区、指标网格各做一个同尺寸的骨架占位（灰块 + 1.4s 微光动画），保证 布局零位移；② 所有数值容器预设 min-height 与 font-variant-numeric: tabular-nums；③ 首次进入时把 #market-state 的「连接行情中」改为带旋转点的动态指示，让「正在工作」可被感知。骨架动画需包在 @media (prefers-reduced-motion: no-preference) 内——当前已有全局 prefers-reduced-motion 兜底，保持这个好习惯。

05P2 · 持续优化项

F-10

字号偏小，层级几乎只靠颜色

视觉语言

轻微

正文基准 13px，但 .hint、.metric .k、.market-stat .k、.panel-note、.count、.unit-label、.log-note 等大量文本落在 9–11px。在 1080p 屏幕上 9px 中文已接近可读性下限。同时标题（12px）与正文（13px）几乎同高，层级差异主要来自颜色而非尺寸。

建议实现 建立一套 5 级字阶并全局替换：--fs-xs: 11px（辅助/时间戳）、--fs-sm: 12px（标签）、--fs-md: 13.5px（正文）、--fs-lg: 16px（面板标题）、--fs-xl: 22px（区块主标题）。全站最小字号提升到 11px，把 .panel-head h2 提到 14px 并加 letter-spacing: .01em，让「标题比正文重」这件事重新成立。
F-11

对比度不满足 WCAG AA

可访问性

轻微

辅助文字色 --ink-3: #839aa9 铺在 --panel: #111b25 上，对比度约 4.0:1，低于 AA 对正文要求的 4.5:1；而它承载了大量 9–10px 的说明文字，实际更糟。--ink-2: #a4b5c2 约为 6.5:1，是合格的。

建议实现 把 --ink-3 提亮到 #9aafbe（约 5.2:1），同时配合 F-10 把最小字号提到 11px。另外 .market-state 绿色 --up 配深底约 6.1:1 已达标，无需调整。
F-12

三层 chrome 挤压数据区

空间效率

轻微

顶栏（≥66px）+ 安全条（33px）+ AI 条（30px）+ 导航（约 40px）= 最多 169px 的固定头部，占 900px 视口高度的近 19%，全部用于状态陈述而非数据。

建议实现 ① 把 .ai-strip 合并进 .safety-strip——两者都是「当前状态一句话」，共用一行、按需切换内容是合理的；② 顶栏在滚动时折叠为紧凑模式（只留 logo + 价格 + 状态点，高度收到 48px）；③ 导航项可考虑与顶栏合并（成为左侧分段控件），再省约 40px。
F-13

工作台与回测报告是两套设计语言

品牌一致性

轻微

工作台是深色 + 金色强调（--bg:#0b1118 / --accent:#dfbc75），回测报告 report.html 是浅色米黄（--bg:#f4f1ea / --ink:#1d232b），且报告的涨跌色用了 --up:#0f766e（青绿）/ --down:#b42318（砖红）——又一套独立的颜色语义。用户从终端点开报告会有强烈割裂感。

建议实现 抽出 tokens.css 作为两处共用的设计令牌来源，至少统一三件事：强调色（统一金色系）、涨跌色（统一为红涨绿跌，与 F-01 一致）、字体栈与语义色命名。报告页可保留浅色底（打印友好是合理需求），但强调色与涨跌语义必须同源。
F-14

K 线图缺少专业分析能力

数据可视化

轻微

当前 K 线是静态 SVG：无十字光标、无缩放/平移、无均线或成交量副图，<title> 悬浮提示是唯一的读数方式（原生 tooltip 有约 1 秒延迟，无法快速扫读）。同时 preserveAspectRatio="none" 会让蜡烛实体随容器宽度被横向拉伸，不同窗口宽度下形态不一致。

建议实现 ① 加一条跟随鼠标的十字光标，交点处常驻显示 时间 / 开高低收 / 涨跌幅，比 tooltip 快得多；② 把 preserveAspectRatio 改为 xMidYMid meet 或改用固定内部坐标系，保证蜡烛比例稳定；③ 增加均线叠加开关（复用策略里的 MA 参数）与成交量副图，让图表与「策略在做什么」建立联系；④ 均线/成交量颜色不要复用涨跌色，避免语义冲突。

按「先修正确性，再修结构，最后加能力」排序。前两个阶段完成后，UI 的一致性与可用性会有质的提升，且不涉及任何后端改动。

阶段一 · 修正语义与故障（P0）

预计 0.5–1 天 · 纯 CSS 变量与少量 JS
  • F-01 拆分「方向色」与「风险色」，统一为红涨绿跌（含 report.html）
  • F-02 统一侧栏断点，修正误导性注释，窄屏保留设置入口
  • F-03 增加独立的新鲜度心跳，过期行情给出视觉告警

阶段二 · 重构层级与反馈（P1）

预计 2–3 天 · 布局重排 + 交互补齐

  • F-08 提示条改造为可堆叠、可自动消失的 toast
  • F-09 补骨架屏，消除首屏布局位移

阶段三 · 补齐专业能力（P1–P2）

预计 3–5 天 · 表格与图表交互

  • F-14 K 线加十字光标、均线与成交量副图
